# 什么时候 LoopX 不是答案

前几章说明了长程运行要求什么、LoopX 怎么回答。这一章反过来：**它不解决什么。**

这个方向比听起来重要。一份说不清自己边界的架构说明，读者无法判断该不该采用它——只能选择相信或不相信。而"它拒绝做什么"是可以在代码和协议里核对的，比"它能做什么"更接近设计本身。

## 一个用错工具的场景

```text
周一  开发者在自己的仓库里引入 LoopX，为一个"给函数加类型标注"的任务。
周一  任务本身 20 分钟能做完。
周一  接入花了两个小时：连接、bootstrap、理解 Todo 怎么写、
      理解 Gate 什么时候要人。
周一  改完了。但为了走完受治理的流程，又花了时间写回 state、
      记录 evidence、确认 quota spend。
周一  开发者得出结论："这东西太重了。"
```

这个结论是对的，但原因常常被说错。问题不在于 LoopX "太重"，而在于**那个任务不需要它**：范围封闭、能在一次上下文内完成、没有外部等待、没有交接。对这类任务，控制面提供的每一项能力都用不上，成本却全额支付了。

## 四条明确的拒绝

### 一、它不拥有你的目标

LoopX 拥有工作队列、权限、证据和恢复条件。它**不判断**一个 issue 值不值得修、一个实验指标是否显著、一段文案是否合适——那些是领域判断，属于 Capability 与项目自己的事实源。

后果很实际：如果一个任务的成功标准无法写成可观察的 acceptance，LoopX 帮不上忙。它会忠实地记录"你说过要做"，但无法告诉你"你做成没有"。

**判据：说不出什么证据足以判定完成，就先不要接入。**

### 二、它不保证单轮快

第 6 章讲过：每一轮都要先读状态、再判断合法性、再验证、再写回。这些步骤换来的是中断后的可恢复性，代价是比"直接开干"慢。

所以 LoopX 优化的是**跨天、跨中断的总体可靠性**，而不是单次执行的延迟。如果你的瓶颈是"每次调用太慢"，接入控制面只会让它更慢。

**判据：你愿意为可恢复性牺牲单轮速度，才值得接入。**

### 三、它不做通用记忆

第 4 章会详细说明状态底座，这里先说边界：LoopX 记录的是**工作生命周期事实**——目标、工作项、Gate、证据、花费、恢复条件。它不打算成为你的知识库、代码索引或偏好记忆。

把"记住上次讨论的设计"这类需求交给它，会得到一个既不完整也不方便的东西；那类需求有更合适的载体。

**判据：需要记住的是"谁在什么时候做了什么决定"，而不是"我们聊过什么"。**

### 四、它不替代 harness

LoopX 决定"该不该干、干什么、干完了算不算"。它**不负责**模型怎么推理、工具怎么调用、上下文怎么压缩——那是 harness 的职责。

这个边界意味着：LoopX 不能修复一个推理能力不足的模型，也不能把一个不会用工具的 harness 变成会用。它只能保证**在这两者之上，工作的生命周期是清楚且可审计的**。

**判据：你遇到的问题在"下一步做什么"，还是在"怎么把这一步做好"？后者不是它的问题。**

## 什么时候普通会话就够了

| 特征 | 为什么不需要控制面 |
|---|---|
| 范围封闭，20 分钟能做完 | 状态外置的成本高于任务本身 |
| 不等待任何外部事件 | 没有需要跨会话保留的等待 |
| 不需要交接给其他人或 Agent | 所有权不需要在会话外恢复 |
| 失败后可以低成本重做 | 恢复机制的价值低于重做成本 |
| 验收标准就是你自己的判断 | 不需要机器可读的 evidence |

这些条件同时成立时，用普通会话是**正确选择**，而不是"还没准备好"。第 2 章的任务资格卡给的是同一组判据。

## 代价与边界：这些拒绝换来了什么

每一条"不做"都对应一个"做得更好"：

| 它不做 | 换来 |
|---|---|
| 不拥有领域判断 | 三个完全不同的领域共用一套控制面 |
| 不保证单轮快 | 中断后可以准确恢复 |
| 不做通用记忆 | 状态底座保持小而可判定 |
| 不替代 harness | 换模型、换 Host 不需要重写控制面 |

**这也是为什么"它不做什么"比"它能做什么"更能说明设计。** 一个什么都做的系统，必然在每个方向上都很浅；而这些拒绝划定的边界，正是它能在长程可靠性上做深的原因。

## 不变式

1. **说不清验收标准的任务，不该接入控制面。** 它会忠实记录，但无法判断完成。
2. **接入的收益随时间跨度增长。** 任务越短，成本占比越高。
3. **它拥有生命周期，不拥有领域。** 判断"值不值得做"始终是 Capability 的职责。
4. **单轮速度与跨天可靠性是一组取舍。** 想同时要，就得接受其中一个变差。

这四条合起来是对一个问题的回答：**这个任务需要的是更好的执行，还是更清楚的记录？** 如果是前者，LoopX 不是答案——而知道自己不是答案，是它可用的前提。
